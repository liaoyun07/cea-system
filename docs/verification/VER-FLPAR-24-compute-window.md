# FLPAR-24 读取完成至写出前的计算区间试验

2026-09-18，源码基线c52b99c，保留既有未提交工作。用户授权一次预热＋三次正式隔离测试，不替换失败，不改变正式计量定义。四次实际执行均SUCCESS，模型与区间验证通过；新计算口径正式均速1.262GB/s、最好1.636GB/s，仍未达到2GB/s。原完整SDK口径同次均速0.516GB/s；这是计量区间对比，不是算法性能提高。

## 范围与实际调用链

沿用par22-candidate：CIFAR10，三客户端各一个边缘，累计100000条/唯一50000条，每源样本两份；分片33334/33334/33332，线性3072→10，rounds1/epoch1/batch1024/seed13/lr0.01/单线程，完整10000条评估。

实际本机运行的是IDEA后端18185、前端18100。首次连接原18085被拒绝，未提交任务；核对IDEA配置及健康后使用已在运行的入口，没有切换或重启服务。不能把本批与9月16日Docker后端的1.3GB/s直接作为配对性能对照。

新增一个固定NamespaceFile `diagnostics/flpar24-compute.py` r1、一个隔离Flow `par24-compute-window` r1，实际页面可查看。复用原fl-preprocess/par22-v1（镜像par18）及init/train/aggregate/evaluate的par21-v1，不新建镜像或应用版本，不修改原Flow、数据集、SDK、资源容量和通用执行链。

原Flow→Worker→Job→文件助手不变。实验入口普通完整加载全部张量（mmap=False），再开始compute计时；compute包括模型构建/参数装载、数据检查、内存分配、归一化、训练/聚合/评估及结果整理，到序列化写出前结束。原SDK覆盖全部读/算/写。额外compute-profile.json在原SDK成功结束后写出，不计入业务字节；失败不生成成功profile。

分子仍为原SDK登记的真实业务输入＋输出逻辑文件长度；分母分别取完整区间或compute区间的并集，不能直接相加子任务时间或取最长任务。分段read/write也记录，但不把其区间并集简单相减构造compute；三类区间在不同任务间可能重叠。计时同时记录UTC纳秒与单调钟并检查一致性，未修改原SDK容差。普通完整加载排除mmap惰性文件加载，但不保证操作系统绝不换页，也不排除CPU等待、内存分配和回收。

## 结论与限制

- 排除文件读写后数值提高，但没有达到2GB/s；既不能声称代码优化带来该倍数加速，也不替换M01原验收口径。
- 预处理的内存计算/分配区间仍较慢且有波动，训练计算重叠较少；磁盘文件保存不是唯一影响项。
- 本批没有进一步拆开预处理compute内部的检查、LUT与分配，不能把整个区间全部归因于归一化算术或硬盘。
- 运行期间的只读Linux快照观察到约1.74GiB已用swap及全局内存/IO压力；edge-a父cgroup2GiB限制、约87MiB swap，历史max/oom/oom_kill计数为0。它们是单点与累计值，不是各任务同区间增量，不能据此证明本次慢任务由OOM、换页或CPU限流造成。没有改配额、清缓存、关闭swap或重启宿主。
- 同次完整指标包含实验脚本少量计时开销，且训练从mmap变为普通加载；不是“原未插桩程序”的严格零扰动复测。不把当前低于旧批次的速率归因于某个单一改动。
