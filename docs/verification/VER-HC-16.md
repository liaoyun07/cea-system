# VER-HC-16：固定资源的32→48→32并发小对照

2026-10-17。源码基点`dd510a68a2ddbbf924e5f9b7462e735ff62471e0`加本批实验脚本变更。**48 VU没有提高吞吐：三轮30秒依次1.460758、1.186767、1.275676 GB/s，10747批全成功，但均有漏发，未达2 GB/s。**后32比前32低12.67%，存在环境/顺序漂移，不能把全部跌幅视为增加VU的稳定因果效果。

## 范围与固定条件

用户授权32→48小对照。四集群新隔离命名空间`cea-hc16-20261017`、NodePort31096；沿用`cea/hydraulic-resident:hc15-fixed`镜像（ID `sha256:db90991c668854da7a5a8c2730e17fd6994518b84e58eb188d5006a68e04b7e8`）。

- 原2205周期分35批，每批64周期、末批29周期，共385257600原始信号字节，循环同一数据计划。算法、NPZ协议、业务计算并发及buffer复用不变。
- 三边缘各2核/2GiB、中心2核/1GiB；k6为7核/5GiB，GOMEMLIMIT4096MiB、GOGC50；实际配额逐轮核验。
- 固定273批/s，名义3.00500928 GB/s；仅将PRE_ALLOCATED_VUS/MAX_VUS同时32→48→32。32预热10秒、32正式30秒、48健康探测10秒、48正式30秒、32返回30秒，逐档检查后执行。未追加64 VU或长测。
- 保留capacity保护：新OOM、危急可用内存或监控失败停止，业务/计量失败不重试；未改变CPU/PSI保护口径、WSL、旧环境或数据库。

主链路仍是k6三路上传→三边缘真实计算→转发特征→中心融合→读取并核验结果。每批是三路合起来的完整业务批次，不将三个上传各算一批。速率=正确完成的原始信号字节÷首HTTP发起至最后结果完成秒数，包含传输、处理、等待与收尾，不含部署启动/持久化，不用中间特征或网络总字节抬高分子。

三轮窗口内实际发起原字节率1.468452/1.191521/1.282905 GB/s，均未承接3.005。`dropped_iterations`是没有空闲VU而未发出的到达，不是已处理批次失败；48还有2次窗口结束后才开始上传。return轮受k6整数纳秒调度影响多一个到达槽，保留3496+4695=8191与名义8190，不删减漏发。全部`offeredLoadAchieved=false`，不能把目标3GB/s当实际输入。

预热32：1136批全成功、1.233934 GB/s、1595漏发/2迟发；探测48：886批全成功、0.955662 GB/s、1845漏发/4迟发，两者不计正式对照。五轮总12769批全成功，客户端/三边缘/中心字节及完成数一致，pending/unconsumed/errors均0；每批核验inputBytes/cycles/flagCount/scoreSum。全175数组逐元素比对是在压测前另行完成，不是每批回传全部数组。
