# VER-HC-17：低复制输入的隔离对照

2026-10-17至18日（Asia/Shanghai）。源码基点 `a7e290aa2bc304274e2747cbd7478292222edbdb` 加本批变更。**数据通路优化及隔离验证完成，性能明显提升，但尚未稳定达到2 GB/s。**

30秒前旧版/新版/返回旧版分别 **1.360065 / 2.015371 / 1.403634 GB/s**。新版三次60秒确认分别 **1.982039、2.007454、1.987775 GB/s**，平均 **1.992423 GB/s**，32594批全成功；相对前后旧版短测提高 **41.95%～46.49%**。旧版前后漂移+3.20%，不把单一比例当普遍因果增幅。两轮长测低于2 GB/s，不能四舍五入后写成达标；全部有漏发，也未承接目标3 GB/s。

## 授权范围与实现

用户授权优化压测端到边缘的数据通路并验证。仅常驻液压实验的 `/process` 大输入由原NPZ增加可选的连续二进制数组表示，读取后构造只读视图；特征打包后释放原输入及透传的 `cycle_ids` 视图，再同步转发云端。

- 新增 `resident/input_codec.py`、`resident/test_input_codec.py`；修改该实验的 service、fixtures、Dockerfile及rate脚本/测试，新增[输入协议](../contracts/hydraulic-resident-input.md)。无Java类、表、数据库字段或平台公开API变化，不涉及Kestra通用工作流语义。
- 新类型为 `application/vnd.cea.hydraulic-arrays`：4字节小端目录长度、最大4096字节JSON目录，每项通道名/dtype/shape；原数组C-order字节、起点8字节对齐，仅小端float32/int64。既有 `/process` NPZ兼容，`/partial`、`/binary`、expected文件仍NPZ。
- 保持原信号、周期、通道、精度、原生统计核、云端融合、计算槽、中心锁和完整HTTP链路不变。不是省略计算、缓存结果、通用K3s优化或普通流任务改造。
- 原NPZ来自 `np.savez`，本来就是未压缩格式，本次减少的是包装拆读、数组物化和大输入保活，不是“取消解压”。采用NumPy既有 [`frombuffer`](https://numpy.org/doc/1.26/reference/generated/numpy.frombuffer.html) 视图语义；[`savez`](https://numpy.org/doc/1.26/reference/generated/numpy.savez.html) 用于既有NPZ路径。小目录是本实验协议，不宣称属于Kubernetes或NumPy标准协议。
- 零复制仅指从已读入的不可变请求体建立数组视图，不表示HTTP收包、内核网络或小特征编码没有复制。

旧镜像 `cea/hydraulic-resident:hc15-fixed` 保留，ID为 `sha256:db90991c668854da7a5a8c2730e17fd6994518b84e58eb188d5006a68e04b7e8`。新镜像 `cea/hydraulic-resident:hc17-views` ID为 `sha256:8ef1c18e7711420a93fc46019f1d97cee2c132d504f97c377204d400b0d1a003`，不覆盖历史标签。各阶段业务源码从实际prepare镜像容器归档；没有将当前工作树的新service当作旧镜像源码。
