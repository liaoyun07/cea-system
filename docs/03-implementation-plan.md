## 后续每次实现的工作循环

S1工作包：S1-01领域模型与JSON/YAML校验；S1-02不可变修订与并发保存；S1-03幂等提交、事务队列和顺序Log；S1-04HTTP、身份和查询；S1-05真实MySQL并发/重启验证、文档与代码索引。全部通过才能完成S1。

1. 从下一阶段选一个可验收工作包，不跨阶段默认扩展。
2. 先补功能规格及其对应 Java 文件/接口设计；重大取舍写 ADR。
3. 实现最小逻辑与必要鲁棒性；增添对应测试。
4. 更新协议、实际代码索引和功能状态。
5. 运行相关检查，记录环境、版本、通过/失败及尚未覆盖的项目。
6. 更新进度与下一步；发现范围变化时修订本计划。

## 计划调整规则

可调整顺序、拆分工作包、后置非必要功能。修改需写明原因、影响功能、依赖变化与新的验收条件。稳定阶段/功能编号不重复使用，不删除失败记录。不能通过缩减验收条件把未完成工作改成完成；范围裁剪必须明确标记。

当前已通过的阶段若因变更失效，应在进度中标为“需重新验证”，不能沿用旧验证结果。
