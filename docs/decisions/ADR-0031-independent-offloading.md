# ADR-0031 独立卸载执行链

状态：已实施（2026-10-15，OFF-INDEP-01）。实测见 [验证记录](../verification/VER-OFF-INDEP-01.md)。

终端按泊松到达产生请求，携带文件大小、本地未完成输入字节数和串行上传预计等待秒数。所属边缘网关读取本边缘积压并查询中心云执行服务积压，按 `[D,Qlocal,Wupload,Qedge,Qcloud]` 决策。固定配置不进入状态；无历史序列/LSTM。本批实现 LOCAL/RANDOM 和五维模型推理入口，不训练 DQN，也不使用旧六维权重冒充新模型。

每边缘拥有自己的网关与执行队列，中心云服务只接受/执行远程任务。选择后立即登记目标积压；输入就绪才进入可执行队列。相同终端本地计算与上传互不阻塞，每个终端上传 FIFO 串行，云边同限速、不同应用层附加时延，附加时延占用上传槽。远程直接创建 k3s Job，不创建 Flow/Execution/TaskRun/Attempt，不调用通用 Worker。结果保存在执行地，回报摘要和阶段时间。

新增 Python 独立运行包，各角色共享基础代码，不共享网关运行状态。MySQL 新增 `offlab_*` 表保存实验、请求、终端资源采样；执行服务重启发现未结束记录则停止启动，不猜测失败、不重新提交；控制服务重启保留中断实验。此阶段不做高可用恢复，遗留实际 Job 必须核对后才能清理或再实验。控制服务管理实验与读统计，不在逐请求决策路径。Java 仅通过窄 HTTP 代理进行用户鉴权和前端集成，不持有运行队列、不跨模块读表。复用原算法、泊松生成语义、cgroup 采集口径和已有基础服务，不直接调用有流引擎依赖的 Runner。

本批不是通用工作流执行能力的修改，不改 Kestra 对应的工作流语义。旧流程/网关/终端保持。每任务结束释放执行额度，但不删除产物；整批停止产生请求且任务全部终态后，先保存统计，再清理本批文件、容器、Job/Pod。清理不计入任务耗时，清理失败不改计算结论。禁止删除共享原始数据和既有实验记录。

公平测试：相同终端、配置、seed、计划到达时间及文件序列，LOCAL 和 RANDOM 串行执行、各自排空清理后继续。保留拒绝/失败，不补跑原请求、不只选成功者声称收益；报告均值/P95/整批跨度/完成率及各阶段。应用层附加时延单独标明，实际上传、计算、启动时间真实采集。

集成验证发现旧后端账号不具备 Pod 日志及 Job 删除权限，因此本批改用专用 Namespace/ServiceAccount，并通过 Pod termination message 获取小型结果摘要，不扩大原账号权限。共享 DinD 的容器清理同时按实验 ID 和终端 ID 过滤，避免多个代理删除同一容器。
