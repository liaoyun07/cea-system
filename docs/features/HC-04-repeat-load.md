# HC-04 多批次流任务资源对照

范围：在 HC-03 两方案上增加完整数据重复 1、5、10 次的独立 Flow。不是把固定数据拆成 1/5/10 份，也不是新增独立样本；每次真实读取、计算、保存全部 2205 周期。累计处理 2205/11025/22050 周期，独立周期始终 2205。每执行仍是集中式一个云 Job，或分布式三个边缘 Job 加一个云融合 Job，完成后退出；不做常驻服务。

同一 hc04 镜像导入原 HC-02 edge/fuse 数值核，以单进程循环摊薄启动开销。输入绑定将同一 S3 原始文件下载为各次独立本地文件，输出各次独立 NPZ；不只乘字节、不缓存结果、不改变数据、资源、阈值、计算核或原观察口径。集中式顺序处理各组并及时释放，分布式逐批边缘处理后云融合。边缘结果全部完成后云任务才启动，不新增跨批流水线调度。

依赖：现有 Parallel、文件绑定、数据集参数准备与四集群。10 次的 30 个业务输入占满现有 inputFiles 上限，共用参考使用已有 REFERENCE 数据集参数下载，再软链接到相同 reference.npz；两个契约仍指向同镜像。没有修改通用编排引擎、Java/API/数据库、权限、前端或运行资源。

验收：镜像原回归加不同批内容的重复处理单测、六个 Flow 文件结构测试、三档各两模式一次预热与五次交替正式执行；全部逐批产物一致、独立数值与原始资源积分重算、旧资源保留。资源目标不预设通过。

计量继承 [HC-03](HC-03-central-distributed.md)：20 个 CEA 服务加四个非重叠 Pod 子树，累计 CPU 核秒及 working set 时间积分，不扣空闲常驻开销。重复下载/读写全部计入；参考文件每任务一份，上云业务字节排除共同参考。SDK按实际各次文件记录，重复处理量不冒充独立数据量。共享宿主及不限额 Pod 根的限制保持公开。

部署新增 `hydraulic-{central|distributed}-repeat{1|5|10}` 六个 r1 Flow、`hydraulic-compare/hc04-v1` 和 `hc04-reference-v1`。原 HC-01/02/03 Flow、应用、数据、历史均保留。

结果见 [验证](../verification/VER-HC-04.md)。
