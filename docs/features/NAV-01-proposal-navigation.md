# NAV-01 申报书业务导航

范围：按用户确认的申报书用语重组前端导航；不重新划分后端模块或改变执行链。

| 分组 | 页面 |
| --- | --- |
| 独立入口 | 运行总览 |
| 云边端协同数据流处理 | 数据流编排、数据流执行记录、数据集管理 |
| 模块化边缘服务部署 | 应用与镜像、镜像仓库、边缘服务部署、服务与访问入口 |
| 智能任务卸载 | 任务卸载决策记录 |
| 多云协作 | 应用分发记录、边缘数据处理策略、边缘数据处理记录 |
| 基础资源管理 | 集群管理、集群运行资源、边缘网关管理、终端设备接入 |
| 系统管理 | 用户管理、个人中心 |

- 左上角、登录页和浏览器标题使用“云边端协同数据流处理系统”。暗色侧栏采用透明轨道、灰紫色细滚动条；保留滚轮、键盘及窄屏横向滚动。
- NAV-01a：模块分组标题由12px浅灰改为16px、700字重和亮灰紫色（#e4dcf1），提高深色背景上的可读性；菜单项目、分组顺序及交互保持。
- NAV-01b：菜单使用纯文字，不再存储或渲染装饰图标；标题继续使用NAV-01a样式。桌面菜单文字相对分组标题缩进10px，普通项400字重、选中项700字重，保留紫色背景/左细线及键盘焦点；选中项悬停不覆盖选中背景。窄屏恢复对称内边距、保留原横向滚动。品牌标识和退出按钮不变，不改菜单名称、顺序、权限或业务交互。
- Service/Ingress 从运行资源页分到“服务与访问入口”；两入口仍使用同一 KubernetesResourcesPage 和原管理组件/API，集群运行资源只显示节点和 Namespace。
- DistributionPage 按应用/版本选择历史。DistributionHistory 同时服务独立页面和应用详情，查询原 preparations API；不新增全局跨应用查询，不把复用镜像误记为一次分发。
- 页面标题、面包屑和菜单同步改名。上传、构建、创建仍是页面操作；日志、Metrics、输出仍是执行详情页签。
- ADMIN 才显示用户管理；原身份、权限、未保存离开提醒保持。
- “智能任务卸载”不表示多核优化已实现；“边缘服务部署”仍可选择 CLOUD/EDGE，不裁剪既有能力。

生产前端新增 DistributionPage.vue、DistributionHistory.vue；没有 Java、DB migration、字段、后端接口、SPI 或运行状态机变更。本次不涉及 Kestra 执行语义修改，只按申报书四条业务主线组织入口。

验收：所有入口/标题、管理员与普通用户可见性、桌面/窄屏、历史刷新/异常恢复、原 Service/Ingress/Namespace 操作和原编排回归。实际结果见[验证](../verification/VER-NAV-01-proposal-navigation.md)。
