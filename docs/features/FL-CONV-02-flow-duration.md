# FL-CONV-02 固定轮数的完整流程耗时实验

用户2026-10-06要求逐组尝试、不增加提前结束能力。复用FL-CONV-01验证集筛选出的共同配置：MNIST三个原训练分片/独立10000测试、主MLP、lr0.1/batch128/epoch1、CADS alpha0.001/rho0.1。首先试Avg10轮/CADS7轮，两2轮预热后五种子31/41/51/61/71交替顺序对照；全部客户端参与、原镜像与资源不变。CADS算法内部总轮数调度仍固定12，不因流程预算7改变蒸馏系数。

指标严格用成功Execution.startedAt→endedAt，包括初始化、文件传输、调度、训练、聚合、评估和流程收尾；不是createdAt→首次评估或单核计时。只有两边最终测试准确率都≥90%才有效，效率=Avg耗时/CADS耗时−1，耗时降低另报；五对每对≥25%且都达标才称这组有限样本达标。探索性试验不能声称独立最终留出验证、精确同准确率或逐轮自动停止。所有未达标/失败保留，不择最快或替换失败；若换预算，须单独批次记录，不覆盖本批。

首组发现CADS种子51仅89.70%、Avg种子61仅89.70%，故其稳定性条件已不成立。第二组单独冻结Avg11/CADS8，选择五个新种子81/91/101/111/121；同原共同配置和CADS内部schedule12。两个Flow复用、不发布新修订，运行时传入轮数；证据独立存放cea-2，首组cea-1不覆盖。新种子能检查非原种子的重复性，但数据仍是同一官方测试集，不能称未参与探索的最终数据验证。

只新增两个实验Flow与一个固定修订Namespace脚本，复用现有八个conv01-v1契约及不可变fedcads-v2镜像。flow_entry.py直接调用原app.run和原算法，使用不采集耗时的文件访问适配，业务异常仍抛出；不输出伪造cea-measurement.json，Flow也不要求它。该批算法内部速率指标不可用是预期，不影响流程真实起止计时。旧公共SDK、原算法/镜像/Flow和计量语义不变，无引擎、Java/API/表/权限修改或服务重启。不涉及新增通用控制流，沿用现有Repeat/Loop。

测试入口见 [实验说明](../../examples/federated/flow-duration/README.md)；真实结果见 [验证](../verification/VER-FL-CONV-02.md)。
