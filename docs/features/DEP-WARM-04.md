# DEP-WARM-04：服务部署预热模式

状态：已发布并完成真实功能验证（2026-10-18）；本批不追加性能收益结论。

## 用户操作

1. 在边缘服务部署选择中心云与命名空间，创建应用；填写原有参数、资源及就绪探针。
2. 启用 HPA，填写副本范围/目标利用率；其下才显示预热池加速选项。取消 HPA 会清除预热选择，再次开启不自动恢复。另一个对照应用不勾选预热即可，不需要新的实验页面。此联动仅作用于创建表单，不改变已部署应用的类型。
3. 使用原 Service/Ingress 操作配置访问入口，外部压测软件发送请求。
4. 打开每个部署详情，查看每副本资源、业务/备用副本轨迹和每次扩缩容耗时。分别读取两次实验记录计算效率，不在页面强行绑定比较。

## 后端语义

`warmPool` 仅创建时选择；常规 Deployment 和 WarmService 共同使用应用契约、镜像分发、参数校验和部署 API。`autoscaling` 的字段复用原 HPA API。流任务 `platform.Deployment` 使用同名配置，仍以配置就绪为任务完成，常驻服务由部署页面管理。

中心云两个授权命名空间各有命名空间内共享备用预算（初始4个/2048MiB），每应用最多2个。最近300秒的正向扩容数量 × 实测冷启动可节约时间 / 内存上限成本，每30秒重算；首次无需求不预填，命中率不固定。预算包含正在启动、终止但仍存在的备用实例。更新配置切换模板/池并替换 Claim；删除 WarmService 由所有者引用回收 HPA、池、模板、Claim。所有者关联采用仅修改 metadata 的 merge patch，不覆盖开源控制器并发更新的标签或状态。

伸缩采集不修改期望副本。副本变化记录真实 desired、已接入 Service 的就绪业务数、备用数。事件以首次观察目标变化为起点，新增实例 Ready 且进入关联 Service 端点为终点；无 Service 时以 Ready 为终点。间隔采样并非内核精确时间，同次采样内完成单独显示。中断/替代/超时/删除记录保留且无成功耗时。预热命中核对之前已 Ready 的备用 Pod UID/containerID，重启不算命中。

## 范围

首次只启用中心云 cea-lab、cea-lab-warm-ui-20261018；旧部署不自动开 HPA/预热，三个边缘集群不改。无热切换模式、无有状态服务持久卷功能、无预设收益率。旧历史不补造。

## 验收

已验证：两模式创建与 Service HTTP、原生 HPA、自然入池和 UID/containerID 复用、配置更新及删除回收；页面创建、宽窄屏详情；platform.Deployment 创建预热服务和 Service；数据库历史保留。真实短测20121请求零错误，两次 HPA 扩容各命中1个备用；不把这个短测当新的性能验收对照。失败及修复经过、回归结果和旧环境审计见[验证记录](../verification/VER-DEP-WARM-04.md)。
