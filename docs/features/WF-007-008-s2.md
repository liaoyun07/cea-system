# WF-007 / WF-008 S2规格

本页保留S2已验收语义，状态见功能索引；验收范围见[S2验证记录](../verification/VER-S2-001-worker-lifecycle.md)。依据[ADR-0004](../decisions/ADR-0004-s2-worker-lifecycle.md)。后续新增控制任务、准入及定时能力见[S3规格](WF-009-011-s3.md)；下文“只实现Log/Sleep”指S2叶子范围，不否认S3控制节点。

- S2-01：持久Worker领取/心跳/结果与epoch隔离；Executor唯一归并运行状态。
- S2-02：任务Constant Retry、持久等待、每Attempt timeout、取消传播。
- S2-03：Flow.errors/finally顺序处理；主错误与清理错误分离；取消仍清理。
- S2-04：真实数据库、跨进程故障、并发、协议、文档验收。S3/S4不扩展。

固定重试type=constant、maxAttempts包含首次、interval为正ISO Duration。只有真实失败/超时才新增Attempt；丢失Worker只重领同一次，旧epoch心跳/结果拒绝。未设置timeout没有业务超时，租约仍可接管。取消为KILLING→清理→KILLED，重复幂等，终态不重启。

只实现Log和Sleep，未知类型拒绝，任务ID跨main/errors/finally唯一。错误处理器失败不递归触发errors。Finally某项失败继续下一项，根cleanupError保留首个，全部失败在TaskRun查看；原始error不被覆盖。主失败、取消时不伪造Outputs。

Log仅归并有效结果时写数据库日志。Sleep没有外部不可逆副作用。不宣称任意外部任务exactly-once；接入外部运行环境属于S4。


取消MAIN/ERRORS终止其后续重试；取消已进入的FINALLY不会重启或中断清理，仍按清理自身retry/timeout执行。每个Attempt的timeout包括等待Worker；没有设置timeout时不自动增加业务时限。

本批新增5个生产Java、1张Worker传输表和2份迁移，无新模块/依赖。取消HTTP操作要求namespace的EXECUTE。具体状态字段、上下文、租约/重复结果规则、停机升级条件及消费者见[S2协议](../contracts/s2-protocol.md)，全部Java见[代码索引](../01-code-architecture.md)。不支持S1/S2混跑，不在新执行路径保留旧Log分支。
