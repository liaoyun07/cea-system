# 五维独立卸载：模拟训练 Double DQN

离线工具，只读实测结果文件，不连接网关、Docker API、MySQL、MinIO 或 Kubernetes。模型导出为现有网关 `offload-five-v1` 格式，不自动部署或切换策略。旧六维训练器保持不变。

## 运行

依赖 Python 3.11、PyTorch 2.2.2 CPU、NumPy；本批复用已有 `cea/federated:gfed-hsam-v1` 的 Python 环境，不执行其训练应用。仓库挂载 `/repo:ro`，新输出目录挂载 `/output`，禁用容器网络，限 2 CPU / 2 GiB。

```sh
cd /repo/algorithms/offloading/simulated
python -B -m unittest -v test_simulation
python -B -u train_sim.py --output /output --episodes 500
```

默认读取 `.local/cea/terminal-load/offload-lab/`，也可通过 `--records` 指定：

- `jitter-LOCAL-result.json`、`jitter-TERMINAL_30-result.json`：主要校准来源。
- `random-result.json`：仅填补没有当前观测的动作/大小组合。它来自旧双槽、512 MiB 终端配置，并非当前配置完整标定。
- `jitter-TERMINAL_30_RANDOM10-result.json`：仅做实测回放误差检查，不用于参数校准。

重新训练使用新的输出目录以保留原模型及报告。原始记录可能含业务信息，不提交；输出只有模型参数、脱敏耗时统计、模拟结果，没有凭据。

## 模拟与训练口径

- 30 端、3 边、1 云，Poisson 到达，5/50/500 MB 比例 60/38/2%；终端单计算槽、独立单上传队列；每边缘和中心云各四计算槽。
- 每终端上传名义 12.5 MB/s，附加边缘 0.01 s、中心 0.1 s，按实测上传时间倍率校准。上传队列和本地计算队列可同时推进。
- 云边接收决策时即增加完整文件字节积压；只有上传就绪才进入计算 FIFO，不能提前按请求次序占据未来槽位。终端积压只含本地任务。
- `finishedAt-dispatchedAt` 为服务时间，含启动、容器内读写和计算，不再加上传/执行排队；`observedAt-finishedAt` 单独占用槽位与积压，模拟观察完成后才释放。
- 状态复用生产五维归一化：文件大小、本地积压、上传等待、所属边缘积压、共享中心积压；字节换算 MB 后 log1p，等待秒数 log1p。策略看不到未来任务或模拟内部完成时间。
- 名义环境使用各耗时中位数。随机环境使用实测 p10/p50/p90 三角分布，各位置服务时间和上传倍率再乘每批独立 U(0.8,1.2)。范围是本批声明的参数不确定性，不是已证明的真实分布。
- 训练网络 5→64 ReLU→3，三个动作全部可选。Double DQN、Adam 0.001、gamma 0.95、回放 50000、batch 128、每约 8 个新样本更新一次、每 200 次更新同步目标网络；epsilon 从 1 下降到 0.05。
- 每个任务奖励 `-端到端秒数/120`，120 只是缩放系数，不是新超时。任务排空后收集奖励；下一状态是同一批全局下一个到达请求的决策状态，最后一个决策不 bootstrap。
- 五维是部分观测，下一请求可能来自不同终端；这不是精确 Markov 状态，也没有额外引入历史序列模型。
- 固定基线逻辑冻结在本目录，保持实测原规则与 10% 扰动分布；生产 `choose` 仍用于 LOCAL/RANDOM 和导出推理核验。

## 隔离训练、验证和测试

三个训练种子 17/29/43，各 500 批，到达种子 1000..1499，平均间隔从 6/8/10/12/15 秒选择。验证种子 20000..20005 × 间隔 6/10/15 秒，按平均单任务耗时选择检查点和训练种子。测试固定为 30000..30019 × 6/10/15 秒，在模型冻结后各跑名义与扰动环境，禁止用测试分数选择权重。

同一测试场景各策略使用相同到达轨迹、文件类型及每任务/动作随机耗时；不强制固定去向比例。报告的均值是各批统计量等权平均，不是汇总任务加权均值。P95 列也是逐批 P95 的平均，不是所有任务合并后的 P95。

产物：`model.json`、三个候选模型及训练日志、`calibration.json`、`calibration-check.json`、`test-runs.json`、`behavior.json` 和 `report.json`。本次保存在 `.local/cea/offload-sim-dqn/`。

## 边界

没有 CPU/内存消耗仿真，没有共享宿主机争用、数据库饱和、HTTP 调用阻塞的精确模型；终端上传等待只近似线上剩余 paced bytes，不能视为真实网络测量。大文件样本较少，旧配置回填存在偏差。不模拟任务失败，也不能给出真实成功率。

优化平均任务时延不等于优化批次跨度。模拟性能不能作为真实验收结果。上线前需要在当前资源配置下少量真实对照；本批没有接通页面 DQN 选项或修改线上模型。

见 [验证记录](../../../docs/verification/VER-OFF-SIM-DQN-01.md)。

## 第二次训练（OFF-DQN-TUNE-01）

`python -B -u refine.py --output /output` 将产物写入新的 `.local/cea/offload-sim-dqn-v2/`，不覆盖v1。校准使用当前64MiB/四槽的固定、扰动、首轮DQN混合负载记录；只缺终端500MB，以当前全终端记录补齐，不再引用旧512MiB/双槽记录。原始五维、奖励、上传/计算模拟结构和线上资源不变。

隐藏层128、Adam学习率0.0005；回放按文件档位×动作分9桶，每桶最多5500条，每个batch等概率抽桶再抽样，避免2%的大任务在训练中被淹没。属于显式均衡采样，没有重要性权重校正，改变了拟合样本权重，但未更改奖励或真实任务分布。三种子17/29/43各800批；到达seed5000..5799、验证40000..40005、测试50000..50019，三者不重叠。选模只用验证平均时延，冻结后再看测试。

此次校准适合混合卸载，不精确模拟完全无上传时终端的较快运行；不能用模拟LOCAL收益替代实测。大文件样本仍只有各7～14条，不代表完善标定。真实复测仍使用seed31的同277任务，这是已用于校准的场景重复测量，不是新的独立泛化验证。相关结果见[二次优化验证](../../../docs/verification/VER-OFF-DQN-TUNE-01.md)。
